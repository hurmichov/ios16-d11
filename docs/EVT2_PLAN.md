# EVT2 — Build System (детальный план, macOS)

Цель этапа: из официальных образов собрать **полный набор экспериментального образа** для
D11 и описать его в `build-manifest.json`. Загрузка/прошивка — это уже EVT3; EVT2
заканчивается на собранных артефактах.

Хост — macOS (нативный APFS, Apple-тулзы). Подход — yigitzra1n (см. `APPROACH.md`).
Конвейер управляется профилем `profiles/d11-ios16.toml`, по умолчанию dry-run, каждый шаг
пишет входы/выходы и их SHA-256 в `build-manifest.json`.

Легенда статуса: **[готово]** реализовано · **[известно]** понятная работа, техники известны ·
**[ресёрч]** неизвестный объём · **[риск]** потенциальный блокер.

## Предпосылки

- выполнен EVT1: `COMPAT_MAP.md` и `KEXT_MAP.md` заполнены;
- три IPSW в `~/halcyon/ipsw/` (база 7Plus 15.8.x, донор iPad7 16.7.x, донор 8Plus 16.7.x);
- инструменты macOS: `xcode-select`, Homebrew, `img4tool`, `lzfse`, `zstd`, `hdiutil`/`asr` (в системе).

---

## Шаг 0. verify-inputs — **[готово]**
Проверка наличия, версий и SHA-256 всех IPSW; CRC zip. Уже работает.

## Шаг 1. extract — **[готово, расширить]**
Извлечение компонентов нужной identity (`d11ap`, `j171ap`) из IPSW по путям BuildManifest.
Сейчас достаёт сырые файлы. Добавить: авто-распаковку IM4P (`img4tool -e`) и lzfse для ядра.

## Шаг 2. kernel-patch — **[известно / ресёрч]**
**Цель:** пропатчить ядро донора iPad7(16) под запуск на D11 и без SEP.
**Вход:** KernelCache донора SoC. **Инструмент:** свой патчер Mach-O (LLVM libObject) + patchfinder.
**Что патчим (ориентир по yigitzra1n, ~23 патча):**
- AMFI / code-signing enforcement (разрешить ad-hoc подпись);
- sandbox/launch constraints там, где мешают;
- флаги SEP-less (`sepfw-load-at-boot=0`) и связанные проверки keystore;
- мелкие платформенные правки (PMU/charger).
**Выход:** пропатченный kernelcache (пока без релинка). **Риск:** patchfinder по сигнатурам
под конкретный билд 16.7.x — сигнатуры придётся выверять на реальном ядре. **[ресёрч]** по объёму.

## Шаг 3. kext-relink — **[ресёрч / риск]**
**Цель:** вшить драйверы D11, которых нет в ядре 16 (из `KEXT_MAP.md`), перелинковав из ядра 15.
Полный разбор — в `ARCHITECTURE.md` и отдельном плане kext-relink. Инвентаризация и diff
(`halcyon kernel diff`) — **[готово]**; сам релинкер (перебазирование, разрешение символов ядра 16,
перезапись chained-fixups, записи в `__PRELINK_INFO` и `LC_FILESET_ENTRY`) — **[ресёрч]**.
**Риск:** драйверы, завязанные на изменившийся KPI 15→16, релинком не чинятся (категория C).

## Шаг 4. dt-merge — **[известно]**
**Цель:** собрать DeviceTree для D11 под ядро 16: взять DT D11 из 15 и внести правки из DT iPad7(16).
**Инструмент:** `devicetree.py` (parse/serialize/diff уже есть) + img4-обёртка.
**Правки (ориентир yigitzra1n):** сенсор, Wi-Fi/BT, камера, аудио, внутр. микрофон, CHRP NVRAM,
SEP-less флаги. **Выход:** `DeviceTree.d11ap.img4`. Механика понятна; какие именно узлы править —
определяется на EVT3 по логам.

## Шаг 5. trustcache — **[известно]**
**Цель:** trust cache, покрывающий все наши ad-hoc-подписанные бинарники (ядро, kext, демоны RootFS).
**Как:** посчитать CDHash каждого бинарника → собрать блоб trustcache (формат известен) → обернуть в img4.
**Выход:** `StaticTrustCache.img4` + trustcache для ramdisk. **Зависит от** финальных бинарников шагов 2–3 и 7.

## Шаг 6. ramdisk — **[известно]**
Два диска, как у yigitzra1n:
- **Restore RamDisk** — для первичной установки (патчи `options.plist`, `asr`, trustcache);
- **Maintenance / OpenSSH RamDisk** — SSH-доступ (`alpine`), диагностика.
**Как:** `hdiutil create` → смонтировать → наполнить (Procursus OpenSSH, launch-демоны) → img4-обёртка.
**Выход:** два ramdisk-образа + их booter.

## Шаг 7. rootfs-assemble — **[известно по механике / ресёрч по содержимому]**
**Цель:** гибридная RootFS: системный том iOS 16 (донор) + прошивки и правки под D11.
**Почему именно macOS:** здесь работаем с APFS нативно (`hdiutil attach` донорского dmg,
`asr` для переноса в новый образ, повторное запечатывание). Под Linux это и был блокир.
**Содержимое (ориентир yigitzra1n):** патчи `securityd` (soft-AKS для SEP-less), `locationd`,
демон зарядки, launcher sshd, skip-setup, замены дылибов под модель. Все модифицированные
бинарники — ad-hoc подпись → их CDHash идут в шаг 5.
**Выход:** `098-*.dmg` (RootFS). **[ресёрч]** — какие именно правки нужны, выяснится на EVT3.

## Шаг 8. bootchain — **[известно]**
**Цель:** подготовить iBSS/iBEC/iBoot из подписанной 15 и boot-args для tethered-установки.
**Как:** img4-персонализация под ECID устройства (TSS/APTicket на EVT3), инъекция boot-args
(`-v debug=0x8 serial=3 sepfw-load-at-boot=0 rd=md0`).
**Выход:** компоненты bootchain для DFU-установки. Фактическая прошивка/загрузка — EVT3.

---

## Итог EVT2

Собранный набор: пропатченный kernelcache (+ релинкованные kext), DeviceTree, trustcache,
два ramdisk, RootFS dmg, bootchain — всё в `build-manifest.json` с хешами. Два прогона одного
профиля дают идентичный манифест (воспроизводимость).

## Карта рисков

| Шаг | Статус | Главный риск |
|---|---|---|
| 2 kernel-patch | известно/ресёрч | сигнатуры patchfinder под конкретный билд |
| 3 kext-relink | ресёрч/риск | KPI 15→16 у части драйверов (категория C) |
| 7 rootfs-assemble | известно/ресёрч | какой набор userspace-патчей достаточен |
| — SEP | риск | почти наверняка только SEP-less (нет Touch ID/Data Protection) |

Первые стены, об которые реально споткнёмся: **kext-relink категории C** и **достаточность
патчей RootFS** — оба выясняются только эмпирически на EVT3 по логам загрузки.
