# Безопасность и восстановление

## Правила утилиты
1. **Dry-run по умолчанию.** Всё, что меняет устройство или ставит пакеты, только печатается. Реальное выполнение — с `--execute`.
2. **Проверка модели перед записью.** `guard_write()` сверяет CPID `0x8010`, ProductType (`iPhone9,2`/`iPhone9,4`) и соответствие BoardConfig (`d11ap`/`d111ap`). Несовпадение или неизвестная модель → остановка (код 3).
3. **Подтверждение.** Перед записью требуется ввести `да`. `--yes` отключает вопрос — только для автоматизации и осознанно.
4. **Целостность образов.** Каждый IPSW сверяется с SHA-256/SHA-1 из каталога; при несовпадении файл удаляется.
5. **Журналы.** Каждая сессия пишет `logs/session-*.jsonl` с командами, кодами возврата и выводом.

## Перед любым экспериментом
```bash
idevicebackup2 encryption on <пароль>     # иначе пароли и Health не попадут в бэкап
d11ctl --execute recovery backup
d11ctl recovery signed                    # убедиться, что iOS 15.x ещё подписана
```

## Возврат на стоковую iOS 15
```bash
d11ctl recovery restore                   # dry-run: покажет команду
d11ctl --execute recovery restore         # обновление с сохранением данных
d11ctl --execute recovery restore --erase # чистая установка
```
Работает, пока Apple подписывает iOS 15.8.x для iPhone 7 Plus (на 26.11.2026 подписана 15.8.8).

## Про защиту данных
Tethered-загрузка порта, скорее всего, будет работать с отключённым или несовместимым SEP. Это значит, что Data Protection, Touch ID и код-пароль в порту могут не работать. Поэтому:
- эксперименты с портом проводить на **устройстве без личных данных** или после бэкапа;
- порт не должен трогать данные стоковой iOS 15 — цель EVT2: отдельный набор томов или полностью отдельная установка;
- стоковая iOS 15 после восстановления сохраняет все штатные механизмы защиты.
