# Диагностический адаптер на Waveshare RP2350-USB-A

## Что уже есть (`firmware/rp2350-diag`)

- USB-CDC к Fedora: устройство `/dev/ttyACM*`, правило udev создаёт `/dev/halcyon-diag`
- UART0 только на приём: RX на GPIO1, TX в режиме высокого импеданса, пока не дана команда `!tx on`
- кольцевой буфер 8 КБ по прерыванию, метка времени в мкс на каждой строке, счётчики переполнений и ошибок UART
- ADC0 (GPIO26) через делитель 2:1 измеряет уровень линии в покое и сообщает, 1.8 В или 3.3 В на ней
- служебные строки начинаются с `#`, раз в 5 секунд приходит heartbeat
- команды: `!ping`, `!stat`, `!baud <n>`, `!adc`, `!tx on|off`

```bash
export PICO_SDK_PATH=~/pico-sdk      # SDK версии 2.x
sudo dnf install -y cmake arm-none-eabi-gcc-cs arm-none-eabi-newlib
make firmware                        # → halcyon_diag.uf2, зажать BOOT, подключить, скопировать
halcyon boot-monitor --serial /dev/halcyon-diag -v
```

## Электрика: важно

- Отладочный UART в Lightning работает на **1.8 В**, а GPIO у RP2350 на **3.3 В**. Подключать
  можно только через двунаправленный преобразователь уровней (TXS0102 или BSS138). Без него
  тристар или SoC можно повредить.
- Сначала измерить уровень через ADC (`!adc`), потом подключать RX. TX подключать только после
  того, как подтверждён протокол.
- Нужен разъём Lightning breakout (male), к которому есть доступ к пинам ID и данных.

## Эмуляция DCSD

> **DCSD не обязателен для старта.** На раннем этапе хватает консоли pongoOS по USB,
> паник-логов (`halcyon panic`) и verbose boot на экране — см. [ROADMAP](ROADMAP.md), EVT3.
> Serial по Lightning нужен только для «тихого» зависания до USB и фреймбуфера. Этот раздел —
> про тот случай, его можно отложить.

Чтобы чип Tristar в iPhone вывел отладочный UART на контакты данных Lightning, аксессуар
должен представиться отладочным через однопроводный протокол **IDBUS (SDQ)** на пине ID.
Это выбор штатного заводского режима телефона, а не эксплойт: подпись кода, SEP и данные
пользователя не затрагиваются. Открытый референс — **Tamarin Cable** (stacksmashing) на RP2040.

### Что реализовано в прошивке

Физический слой SDQ (`src/sdq.c`) на выделенном ядре с точным таймингом по циклам: открытый
сток, передача и приём битов, детект break, CRC-8 (Maxim/Dallas, тот же, что в IDBUS —
проверен против эталона). Поверх (`src/idbus.c`) — три режима, переключаются по USB:

| `!mode` | Что делает |
|---|---|
| `uart` | мост отладочного UART → USB (по умолчанию) |
| `sniff` | **пассивно** декодирует обмен по линии ID и печатает каждый кадр с CRC |
| `dcsd`  | отвечает на опрос телефона как отладочный аксессуар, затем сам переходит в `uart` |

### Важная оговорка про байты

Тайминги и структура кадров реализованы полностью и корректно. А вот **точные байты команды
«вывести UART на пины»** — это реверс. В `idbus.c` они помечены как `PLACEHOLDER` и в таком
виде телефон в serial-режим, скорее всего, не переведут. Их надо получить достоверно — одним из
двух способов:

1. **Снять сниффером (надёжно, на своём устройстве).** Включить `!mode sniff`, дать настоящему
   DCSD-кабелю (или любому аксессуару) поговорить с твоим iPhone 7 Plus и записать кадры. По ним
   подставить реальные значения `CMD_*` и `RSP_*` и при необходимости подстроить тайминги (`!tmg`).
2. **Взять из исходников Tamarin Cable** (с учётом их лицензии) и сверить.

### Порядок проверки

1. **Фаза 1 (готово, собирается):** UART-мост и пассивный сниффер.
2. **Фаза 2:** по данным сниффера заполнить таблицу ответов, добиться появления UART на пинах D11.
3. **Фаза 3:** убедиться, что iBoot и ядро реально пишут в этот UART (может понадобиться boot-arg
   `serial=3`, который и так ставится при tethered-загрузке).

DCSD считается подтверждённым, только когда на реальном D11 получен лог iBoot. До этого — «не подтверждено».

### Электрика (повторю, это критично)

Линия ID и UART в Lightning — **1.8 В**, GPIO RP2350 — **3.3 В**. Только через двунаправленный
преобразователь уровней (TXS0102 / BSS138). Сначала измерить уровень командой `!adc`, потом
подключать. Прямое подключение может повредить Tristar или процессор телефона.

Порт USB-A на плате (хост через PIO-USB) пока не используется — отдельная задача (сниффер USB
или переходник iPhone↔ПК).
